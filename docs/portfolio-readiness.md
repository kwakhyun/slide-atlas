# 프로덕트 엔지니어 역할 요건과 구현 근거

## 문서 목적

이 문서는 Slide Atlas에서 직접 확인할 수 있는 구현을 AI 프레젠테이션 프로덕트 엔지니어에게 필요한 역량과 연결해 정리합니다. 디자인 온톨로지 운영, 백오피스, AI 프레젠테이션 PoC, 관계형 DB, 검색 실험과 배포는 저장소에서 확인할 수 있습니다. 실제 조직 협업, 외부 운영자 성과와 다양한 실데이터에서의 AI 품질은 이 개인 프로젝트만으로 입증하지 않습니다.

## 역할 요건과 근거

| 요구 역량                            | 저장소에서 확인할 수 있는 근거                                               | 확인하지 않은 범위                    |
| ------------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------- |
| TypeScript, React, Next.js 제품 개발 | Next.js App Router 화면, 리소스별 Route Handler, Zod 경계 검증               | 장기 운영 지표                        |
| 관계형 DB와 직접 작성한 쿼리         | PostgreSQL 스키마, 트랜잭션, 행 잠금, 검색 후보 쿼리, PGlite와 PostgreSQL CI | 대규모 데이터 성능                    |
| REST API 설계                        | 세션 격리, 일관된 오류 형식, 낙관적 잠금, 입력 크기와 출처 제한              | 기업용 인증과 권한 체계               |
| 온톨로지 등록, 수정, 검수 운영       | 템플릿 상태 전이, 버전 사본, 변경 비교, 감사 이력                            | 외부 운영자의 판단 일치율과 작업 시간 |
| AI 프레젠테이션 PoC                  | 구조 검색, 내용 편집, 스타일 변경, PPTX 가져오기와 내보내기                  | 다양한 실데이터의 생성 품질           |
| 빠른 실험과 다음 판단                | 기준선 비교, 평가셋과 카탈로그 해시, 실패 사례, CSV, 독립 홀드아웃 실행기    | 독립 홀드아웃 결과                    |
| LLM API 경험과 한계 설명             | OpenAI strict schema, 비용 제한, 자동 품질 평가, 사람 평가 경계              | 24개 입력의 라이브 평가와 사람 검수   |
| 운영 성과와 협업 경험                | 이 프로젝트에서는 확인하지 못했으며 별도의 경력 근거가 필요함                | 외부 사용자 결과와 팀 협업 과정       |

## 먼저 확인할 구현 근거

1. 온톨로지 등록부터 승인, 생성, 편집, 평가까지 연결한 제품 흐름
2. PostgreSQL 트랜잭션, 생성 당시 템플릿 사본 참조와 저장 중 편집 잠금으로 작업을 보존하는 설계
3. AI가 바꿀 수 있는 범위를 슬롯 텍스트로 제한하고 자동 검사와 사람 검수를 분리한 판단
4. 개발셋 수치의 한계를 공개하고 독립 홀드아웃과 외부 운영자 검증 절차를 별도로 마련한 평가 설계
5. PGlite와 PostgreSQL의 직렬화 차이, Vercel과 Docker의 빌드 차이를 발견하고 해결한 배포 경험

## 아직 필요한 외부 검증

- 구현에 참여하지 않은 평가자가 검색 홀드아웃 24개 이상을 완성해야 합니다.
- 운영 경험자 3~5명이 [사용성 과제](user-study-protocol.md)를 수행해야 합니다. 수정 횟수와 막힌 단계를 포함한 기록 양식과 미완성 입력을 거절하는 집계 도구는 준비했습니다.
- AI 합성 입력 24개를 실제 모델로 평가하려면 비용 승인이 필요하며, 의미와 수치 연결은 두 명이 검토해야 합니다.
- 실제 PowerPoint 또는 다양한 외부 제작 PPTX에서의 렌더링과 추출 정확도는 별도 검증이 필요합니다.

이 검증이 끝나기 전에는 `검색 성능 향상`, `업무 시간 단축`, `AI 품질 확보`처럼 일반화된 표현을 쓰지 않습니다. README에서는 `개발셋에서 관찰`, `합성 왕복 검사`, `연결 검증`처럼 확인한 범위가 드러나는 표현을 사용합니다.
