# Product Engineer 포트폴리오 적합성 점검

## 결론

Slide Atlas는 미리캔버스 Product Engineer 포지션에 제출할 대표 프로젝트로 충분히 관련성이 높습니다. 디자인 온톨로지 운영, 백오피스, AI 프레젠테이션 PoC, 관계형 DB, 검색 실험과 배포를 하나의 제품 흐름으로 연결했기 때문입니다. 다만 개인 프로젝트 하나만으로 실제 조직 협업, 외부 운영자 성과와 다양한 실데이터의 AI 품질을 입증하지는 못합니다. 지원서에서는 구현 범위와 검증된 결과를 앞에 두고, 아래 미검증 항목을 분명히 구분해야 합니다.

## 제출할 때 강조할 순서

1. 온톨로지 등록부터 승인, 생성, 편집, 평가까지 연결한 제품 흐름
2. PostgreSQL 트랜잭션과 버전 충돌 복구처럼 운영 중 데이터 손실을 막는 설계
3. AI가 바꿀 수 있는 범위를 슬롯 텍스트로 제한하고 자동 검사와 사람 검수를 분리한 판단
4. 개발셋 수치의 한계를 공개하고 독립 홀드아웃과 외부 운영자 검증 절차를 별도로 만든 태도
5. PGlite, PostgreSQL CI, Neon, Vercel 사이의 차이를 발견하고 해결한 배포 경험

## 제출 전 남은 외부 작업

- 구현에 참여하지 않은 평가자가 검색 홀드아웃 24개 이상을 완성해야 합니다.
- 운영 경험자 3~5명이 [사용성 과제](user-study-protocol.md)를 수행해야 합니다.
- 24개 AI 합성 입력의 라이브 실행은 비용 승인이 필요하며, 의미와 수치 연결은 두 명의 사람 평가가 필요합니다.
- 실제 PowerPoint 또는 다양한 외부 제작 PPTX에서의 렌더링과 추출 정확도는 별도 검증이 필요합니다.

이 작업이 끝나지 않았다면 `검색 성능 향상`, `업무 시간 단축`, `AI 품질 확보`처럼 일반화된 표현을 쓰지 않습니다. 현재 제출본에서는 `개발셋에서 관찰`, `합성 왕복 검사`, `연결 검증`처럼 근거 범위가 드러나는 표현을 사용합니다.
