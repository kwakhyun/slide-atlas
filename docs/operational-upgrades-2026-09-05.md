# 운영 흐름과 품질 검증 기능 확장

기능 검토에서 발견한 팀 검수, 데이터 등록, PPTX 교정, AI 평가와 작업 복구의 빈틈을 보완했습니다. 기존 UI와 API를 유지하면서 운영자가 여러 계정과 탭에서 작업하는 흐름을 확장했습니다.

## 구현 범위

| 항목      | 현재 동작                                                                                                                                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 검수 권한 | 작성자는 검수 요청을, 검수자는 승인과 수정 요청을 처리합니다. 소유자는 전체 흐름을 사용할 수 있고 열람자는 변경할 수 없습니다. 화면도 같은 권한 기준으로 버튼을 제한합니다.                                          |
| 감사 이력 | 요청별 계정을 분리해 변경 계정 이름, ID와 템플릿·프레젠테이션 버전을 기록합니다. 과거 익명 기록에 계정을 소급해서 채우지 않습니다.                                                                                   |
| 중복 등록 | 일괄 가져오기는 서버의 작업 공간 잠금과 정규화한 JSON 해시로 중복을 확인합니다. 여러 탭의 같은 입력도 같은 템플릿을 반환합니다. 기존 템플릿이 수정됐다면 현재 내용과 다시 비교하며, 의도적인 복제 등록은 허용합니다. |
| 변경 영향 | 이전 버전과 적용할 버전을 슬라이드로 비교합니다. 자동으로 옮기지 못한 내용은 직접 수정하고 포함 또는 제외 여부를 확인해야 합니다. 적용 시 버전과 품질을 다시 검사합니다.                                             |
| PPTX 교정 | 추출한 텍스트의 위치와 원문을 보여주고 역할, 읽기 순서, 좌표, 글자 제한과 내용을 수정한 뒤 후보에 반영합니다. 분석 대기를 취소하고 다시 시도할 수 있습니다.                                                          |
| 품질 평가 | 원문, 결과와 템플릿을 사본으로 보관합니다. 등록자 이외 두 계정이 평가하고, 불일치와 최종 판단 근거를 보관합니다. 실패 사례를 재평가 입력으로 내려받습니다.                                                           |
| 의미 검색 | 키워드, 구조 검색과 임베딩+구조 검색을 같은 승인 템플릿으로 비교합니다. 상위 5개, 정답 지정 시 Hit@1과 RR@5, 호출·토큰 사용량, 연산과 전체 시간을 보관합니다.                                                        |
| 작업 복구 | 생성, 후보 일괄 등록과 템플릿 변경 적용의 항목별 상태와 결과를 서버에 보관합니다. 페이지를 다시 열어 계속 처리하거나 실패 항목을 재시도할 수 있습니다.                                                               |

[품질 평가와 PPTX 교정 화면](screenshots/README.md)에서 데스크톱과 모바일의 실제 실행 상태를 확인할 수 있습니다.

## 품질 평가 사용 방법

실험실의 `AI 결과와 편집 품질 검토`를 열고 저장한 프레젠테이션을 선택합니다. 평가 사본은 이후 원본을 편집해도 변하지 않습니다. 검수자 두 명이 각자 다른 계정으로 원문과 결과를 확인하고 의미, 수치 연결, 조건 보존과 사용 가능성을 판정합니다. 한 평가자는 한 번만 판정할 수 있습니다. 두 판정이 다르면 통과로 집계하지 않으며 소유자가 근거와 함께 최종 판단을 남길 수 있습니다.

서로 다른 계정이라는 사실만으로 실제 평가자의 독립성을 입증할 수는 없습니다. 자동 검사나 두 계정의 판정만으로 일반적인 AI 품질을 주장하지 않습니다. 규칙 기반 결과는 모델 기록이 없는 결과로 구분합니다.

라이브 평가 실행기는 공개 지표 파일과 비공개 결과 사본을 분리합니다. 기본 비공개 경로는 Git에서 제외한 `.artifacts/ai-evaluation.private.json`이며 파일 권한은 `0600`입니다. 이 파일을 평가 화면에서 불러와 각 결과를 평가 사본으로 보관할 수 있습니다. 원문이 들어 있는 파일을 공개 저장소나 공유 링크에 올리지 않습니다.

```sh
# 실제 모델 호출에는 비용이 발생합니다. 실행자가 입력과 비용을 확인한 뒤 사용합니다.
npm run eval:ai -- --live --confirm-cost --limit 2
# 내려받은 실패 사례로 다시 평가하는 경우
npm run eval:ai -- --dataset quality-regression.private.json --live --confirm-cost
```

## 의미 검색 사용 방법

실험실의 `의미 검색과 기존 검색 비교`에서 질의와 필요 슬롯 수를 입력합니다. AI가 설정된 환경에서 실험 초대 코드로 실행하며, 검색어와 승인된 템플릿 설명 및 슬롯 역할이 OpenAI에 전송됩니다. 원본 PPTX 파일이나 프레젠테이션 브리프를 자동 전송하지 않습니다.

`OPENAI_EMBEDDING_MODEL`은 기본 `text-embedding-3-small`이며 `text-embedding-3-large`도 설정할 수 있습니다. 256차원 벡터를 사용합니다. 작업 공간, 모델과 입력 해시를 기준으로 7일간 캐시하고 공간당 최근 500개를 보관합니다. 새 임베딩이 필요한 실행만 기존 AI 일일 예산을 사용합니다. 실패한 모델 요청은 자동 재시도하지 않습니다.

의미 검색 점수는 코사인 유사도와 구조 점수의 가중합이며 정확도 확률이 아닙니다. 정답 ID는 순위 계산에 쓰지 않습니다. 상위 5개 안에서의 역순위는 `RR@5`로 표시하며 전체 카탈로그의 MRR과 구분합니다. 실제 입력 토큰 수와 API 호출 수를 기록하며, 청구 금액을 임의로 추정하지 않습니다. 구현 규격은 [공식 Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create)를 따릅니다.

## 작업 상태와 복구

`작업 진행과 실패 복구`는 Studio와 라이브러리 아래에 있습니다. 각 작업은 고정된 입력과 UUID를 가지며 같은 ID를 다른 입력으로 재사용할 수 없습니다. 한 요청은 한 항목을 처리하고, 열린 브라우저가 다음 항목 처리를 요청합니다. 페이지를 닫으면 현재 서버 요청이 끝난 뒤 나머지는 대기합니다. 별도 상시 백그라운드 작업자는 사용하지 않습니다.

- 항목 변경과 완료 결과를 같은 DB 트랜잭션으로 저장하므로, 결과를 받지 못해도 완료된 항목을 다시 생성하지 않습니다.
- 취소는 아직 완료하지 않은 항목에 적용됩니다. 이미 반영된 등록이나 변경은 되돌리지 않습니다.
- 실행 중 서버가 중단되면 2분의 실행 유효 시간이 지난 뒤 실패 상태로 복구할 수 있습니다. 자동으로 모델을 다시 호출하지 않습니다.
- 실패 항목 재시도는 사용자가 직접 시작합니다. 생성 모델은 이전 요청이 과금됐을 수 있으므로 재호출 가능성을 버튼과 오류 안내에 표시합니다.
- 버전 충돌이나 누락 내용은 원인을 수정하고 새 변경 영향 작업을 만들어야 합니다. 오래된 입력을 강제로 적용하지 않습니다.
- 작업 공간당 검색 기록은 최근 20개를 보관합니다. 작업은 최대 100개, 품질 평가 사본은 최대 50개이며 한도에 도달하면 새 등록을 거절합니다. 작업 완료 후에도 입력과 결과가 공간에 남습니다.

## 추가 검증이 필요한 범위

PPTX 원본 위치 표시는 추출된 텍스트의 좌표 도식입니다. 이미지, 표, 차트, 마스터와 그룹 도형의 전체 렌더링을 재현하지 않습니다. 추론 점수도 학습된 정확도 확률이 아닙니다. 외부 제작 문서에 대한 추출 정확도, 실제 모델 검색 품질과 외부 사용자의 작업 성과는 별도 검증이 필요합니다.

이번 구현에서는 실제 모델을 호출하지 않고 모의 응답과 규칙 기반 모드로 검증합니다. 최신 검사 결과와 소스 해시는 [로컬 검증 기록](local-verification.json)에 기록합니다. 독립 데이터와 실제 관찰 결과가 생기기 전에는 처리 시간 단축이나 검색 성능 향상을 성과로 표시하지 않습니다.
