# 운영 역할 기반 시나리오 검증

- 검증일: 2026-09-01
- 환경: Next.js 프로덕션 빌드, Chromium, 파일 PGlite
- 데이터: 프로젝트의 합성 브리프와 앱이 생성한 편집 가능한 PPTX
- 실행 방법: 각 운영 역할의 완료 기준을 Playwright 시나리오로 고정하고, 초기 작업 공간에서 처음부터 끝까지 실행했습니다.

이번 검증은 외부 참여자를 모집한 관찰 연구가 아닙니다. 반복 가능한 브라우저 태스크 실행으로 기능 연결, 오류 처리와 완료 상태를 확인한 결과이며, 아래 실행 시간은 자동화 런타임입니다. 사람의 업무 시간이나 사용성 만족도를 의미하지 않습니다.

## 역할과 완료 기준

| 역할                | 수행 과제                                                                      | 완료 기준                                                                   | 결과 | 자동화 런타임 |
| ------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------- | ---- | ------------: |
| 콘텐츠 운영자       | PPTX 선택 → 구조 분석 → 후보 비교 → 온톨로지 초안 검토 → 저장                  | 원본을 즉시 저장하지 않고 후보와 신뢰도·추출 근거를 확인한 뒤 초안으로 등록 | 통과 |         2.1초 |
| 온톨로지 운영자     | 결과 없는 검색 → 필터 초기화 → 템플릿 등록 → 검수 요청 → 승인 → 감사 이력 확인 | 등록부터 승인까지 상태 전이와 근거가 남음                                   | 통과 |         2.5초 |
| 프레젠테이션 편집자 | 이름 변경 → 복제 → 슬라이드 이동·복제·삭제 → 실행 취소·다시 실행 → 덱 삭제     | 반복 편집과 덱 수명 주기가 화면에서 완료됨                                  | 통과 |         3.4초 |
| 검수자              | 현재 템플릿과 이전 내용 버전 비교 → 자동 검사와 사람 검토 근거 확인            | 승인 전 변경 내용과 조건을 한 화면에서 확인                                 | 통과 |         2.4초 |
| 실험 운영자         | 검색 비교 재실행 → 이전 실행 비교 → 실패·개선 필터 → CSV → 후속 검색           | 실험 결과가 재현되고 실패 사례가 다음 탐색으로 연결됨                       | 통과 |         2.4초 |

## 발견 사항과 반영

- 대형 Studio 대화상자를 분리하는 과정에서 이름 저장 버튼의 접근 가능한 이름이 기존 시나리오와 달라진 회귀를 발견했습니다. 기존 용어인 `이름 저장`으로 복구하고 해당 시나리오를 다시 실행해 통과했습니다.
- PPTX 추출 결과는 저장 전에 후보 선택과 기존 등록 폼 검토를 거치도록 했습니다. 분석 요청만으로 템플릿 수가 바뀌지 않는지 API 시나리오에서 확인했습니다.
- 8MB 파일 제한, 최대 12장 분석, ZIP 항목 수와 압축 해제 크기 제한, 암호화 파일 거절을 적용했습니다. 이미지·표·차트처럼 이번 PoC가 변환하지 않는 요소는 결과에 경고로 표시합니다.

## 판정

정의한 역할 시나리오 5개는 모두 완료됐고 해결되지 않은 차단 결함은 없습니다. 전체 회귀 검사는 Vitest 57개와 Playwright 24개로 구성됩니다. 실제 조직의 업무 속도, 학습 비용과 판단 일치율을 확인하려면 구현에 참여하지 않은 운영자 3~5명을 모집해 같은 과제를 관찰하는 후속 연구가 필요합니다.
