커밋된 런타임 소스와 lockfile을 Vercel에 전달해 배포했습니다. 환경 파일, 자격 증명, 로컬 DB, 테스트 산출물은 배포 파일에 포함하지 않았습니다. GitHub에 푸시하면 CI가 실행되지만, Vercel의 Git 자동 배포 연결은 설정하지 않았습니다. 이번 DB 전환은 서버 환경 변수로 반영했으며, 문서 수정은 위 런타임 코드의 동작을 변경하지 않습니다.

전용 DB는 Vercel의 `slide-atlas` 프로젝트 운영 환경에만 연결했습니다. 개발·미리보기 환경이나 기존 다른 프로젝트의 DB와는 공유하지 않았습니다. 접속 정보는 민감 환경 변수로 등록했으며, 비밀값을 열거나 문서에 기록하지 않았습니다.

새 운영 배포 이후 [상태 확인 API](https://slide-atlas-mu.vercel.app/api/health)에서 로그인 없이 다음 HTTP 200 응답을 확인했습니다.

```json
{
  "data": {
    "status": "ok",
    "storage": "postgres",
    "version": "1.0.0",
    "api": "v1",
    "aiEnabled": false
  }
}
```

초기 공개 데모는 인스턴스 재시작 시 데이터가 초기화되는 메모리 PGlite를 사용했습니다. 현재는 외부 PostgreSQL로 전환했습니다. 보관 정책은 7일이며, 세션 만료 여부는 접근할 때 확인하고 만료 데이터는 다음 작업 공간 생성 시 정리합니다. 쿠키를 지우면 기존 작업에 다시 접근하지 못할 수 있으므로 중요한 결과는 PPTX 또는 JSON으로 내려받아 보관해 주세요.

## 환경별 검증 결과

| 환경                    | DB                   | 확인한 결과                                                         |
| ----------------------- | -------------------- | ------------------------------------------------------------------- |
| 로컬 개발·프로덕션 빌드 | 파일 PGlite          | 정적 검사, 53개 단위·통합 테스트, 17개 E2E 시나리오, 평가 재현 통과 |
| GitHub Actions / Ubuntu | PostgreSQL 17 서비스 | 의존성 설치부터 빌드와 17개 E2E까지 전체 검증 절차 통과             |
| 공개 Vercel 서비스      | 전용 Neon PostgreSQL | DB 전환 후 로그인 없이 17개 Playwright 시나리오 통과                |

PostgreSQL CI의 [성공한 실행 기록](https://github.com/kwakhyun/slide-atlas/actions/runs/33349156955)과 [워크플로우](../.github/workflows/ci.yml)를 공개했습니다. 환경별로 같은 테스트를 반복한 것이므로 테스트 수를 합산하지 않았습니다. Neon 연결 후 공개 URL에서 실행한 17개 시나리오는 38.4초에 모두 통과했습니다.

공개 URL 검증은 다음 명령으로 재현하실 수 있습니다. PowerShell에서 실행하며 별도의 로컬 서버는 시작하지 않습니다.

```powershell
$env:PLAYWRIGHT_BASE_URL = 'https://slide-atlas-mu.vercel.app'
npm run test:e2e
Remove-Item Env:PLAYWRIGHT_BASE_URL
```

E2E 검사는 독립된 데모 공간에 테스트용 데이터를 생성합니다. 다른 운영 서비스에 그대로 실행하지 마세요. 검사 범위는 다음과 같습니다.

- Studio, Library, Review, Experiments, About의 데스크톱·모바일 레이아웃과 axe 자동 접근성 검사
- 대화상자 이름, 키보드 포커스 순환, 모달 닫기
- 브리프 생성, 내용 수정, 스타일 변경 시 내용 보존, 저장·재조회, PPTX 다운로드, 발표 모드
- 템플릿 등록, 검수 요청, 승인 근거, 감사 이력, 실험 실행·조회
- 세션 간 데이터 격리, 잘못된 입력·경로·요청 출처 거절, 요청 한도

실제 OpenAI 응답은 이 검증에 포함하지 않았습니다. AI 테스트 9개는 모의 응답을 사용해 출력 구조, 생성 거절, 불완전한 응답, 원문에 없는 숫자, 요청 예산 제한을 확인합니다. 자동 접근성 검사 통과가 모든 보조기술과 사용자를 대상으로 한 접근성 인증을 의미하지는 않습니다.

## 재배포 후 저장 유지 확인

일반적인 저장·새로고침 검사와 구분해 다음 순서로 검증합니다.

1. 외부 PostgreSQL에 연결된 공개 서비스에서 새 데모 세션을 발급받습니다.
2. 검증용 프레젠테이션을 생성하고 제목을 수정한 뒤, 내용과 버전을 기록합니다.
3. 새로운 Vercel 운영 배포가 완료되면 같은 세션으로 프레젠테이션을 다시 조회합니다.
4. 제목, 버전, 슬라이드 수, 실제 내용과 해시가 모두 유지되는지 비교합니다.

내용 비교 과정에서 저장 직후의 응답과 DB 재조회 결과는 값이 같아도 객체 키의 순서가 다를 수 있음을 확인했습니다. PostgreSQL의 JSONB는 객체 키 순서를 보존하지 않습니다. [PostgreSQL 공식 문서](https://www.postgresql.org/docs/17/datatype-json.html)

따라서 해시를 계산하기 전에 객체의 키만 정렬하고, 배열 순서와 모든 값은 그대로 유지합니다. 해시뿐 아니라 중첩된 객체와 배열의 모든 값도 직접 비교합니다. 검증용 쿠키는 Git에서 제외한 로컬 파일에만 보관하며, 공개 기록에는 포함하지 않습니다. 실제 고객 자료나 OpenAI 호출은 사용하지 않습니다.

**검증 결과:** 서로 다른 두 Vercel 운영 배포 사이에서 프레젠테이션 2장의 제목, 버전 2, 슬라이드 내용이 모두 유지됐습니다. [검증 기록 JSON](persistence-verification.json)에 배포 ID, 확인 시점, 내용 해시와 비교 결과를 남겼습니다. 이 결과는 해당 재배포 시나리오의 보존을 확인한 것이며, 장기 가용성이나 백업 복구까지 검증했다는 의미는 아닙니다.

## 파일과 의존성 검증

독립적인 Python-pptx 파서로 샘플 파일을 열어 슬라이드 4장, 편집 가능한 텍스트 상자 46개, 발표자 노트 4개와 XML 구조를 확인했습니다. Microsoft PowerPoint 화면에서 직접 렌더링을 확인하지는 않았으며, 글꼴 대체나 뷰어에 따른 줄바꿈 차이가 있을 수 있습니다.

`npm audit` 결과는 검사 시점 기준 취약점 0개였습니다. 애플리케이션의 보안 인증이나 이후 발견될 취약점까지 보장하는 결과는 아닙니다. Dockerfile과 로컬 PostgreSQL용 Compose 설정은 제공하지만, 이번 환경에서는 Docker 빌드를 실행하지 않았습니다.

## 배포 중 발견하고 수정한 문제

### PostgreSQL JSONB의 이중 직렬화

로컬 PGlite에서 통과하던 데이터 접근 계층 테스트가 실제 PostgreSQL CI에서 실패했습니다. 이미 직렬화한 JSON 문자열을 `::jsonb` 파라미터로 전달할 때 PostgreSQL 드라이버가 다시 직렬화해, JSONB 객체가 아닌 JSONB 문자열로 저장한 것이 원인이었습니다.

JSON 파라미터에 `::text::jsonb`를 명시해 두 드라이버가 같은 방식으로 저장하도록 수정했습니다. 초기 데이터의 슬롯·버전·슬라이드 구조를 테스트에서 직접 확인했고, PostgreSQL 17에서도 전체 CI를 다시 통과했습니다. 같은 SQL 스키마를 사용하더라도 드라이버의 직렬화 동작은 별도로 검증해야 한다는 점을 확인했습니다.

### Vercel과 Docker의 빌드 산출물

Docker용 `output: "standalone"` 설정을 Vercel에도 적용한 첫 배포는 `.next/next-server.js.nft.json`을 찾지 못해 실패했습니다. Vercel에서는 플랫폼이 Next.js 빌드 결과를 패키징하도록 두고, 로컬·Docker에서만 standalone을 사용하도록 변경했습니다. 수정 후 운영 배포가 정상적으로 완료됐으며, 공개 URL에서 전체 E2E 검사를 통과했습니다.

두 수정은 [`8765dec`](https://github.com/kwakhyun/slide-atlas/commit/8765decef18168bff86537aadb95ecfdd698198f)에 포함되어 있습니다.
