# 프로젝트 기획 — Slide Atlas

## 문제와 가설

AI 프레젠테이션 PoC를 운영 가능한 제품으로 발전시키려면 **재사용할 디자인을 선택하는 기준, 결과를 수정하는 과정, 다음 실험에 활용할 기록**이 필요하다는 가설에서 출발했습니다. 이 가설은 AI 프레젠테이션 제품의 데이터 운영과 기능 검증 과제를 바탕으로 세웠으며, 실제 조직의 내부 업무를 조사한 결과는 아닙니다.

주요 사용자는 디자인 데이터를 관리하는 운영자와 PoC를 검증하는 프로덕트 엔지니어로 설정했습니다. 전달 의도, 레이아웃, 슬롯과 내용량을 데이터로 관리하고, 검수된 구조 안에서 내용을 편집하며, 동일한 조건으로 검색 품질을 비교할 수 있도록 설계했습니다.

## 주요 사용 흐름과 완료 기준

## 구현 순서를 정한 이유

1. **데이터 규칙을 먼저 정의했습니다.** 허용되는 슬롯과 제약 조건을 정해 등록·생성·검수 단계에서 같은 기준을 사용하도록 했습니다.
2. **API 키 없이 체험할 수 있게 했습니다.** 평가자가 전체 사용 흐름을 확인할 수 있도록 규칙 기반 생성을 기본으로 제공합니다.
3. **AI가 변경할 수 있는 범위를 제한했습니다.** 모델은 선택된 템플릿의 슬롯 텍스트만 반환하며, 도형이나 테마, 승인 정책과 DB를 직접 변경하지 않습니다.
4. **실험 결과를 서비스에 남겼습니다.** 실행 이력, 카탈로그 버전, 개별 질의 결과를 화면에서 확인하고 JSON으로 내려받을 수 있도록 했습니다.

## 사용성 검토 후 추가한 운영 흐름

초기 제품을 실제 운영자 관점에서 다시 검토한 뒤, 단절되어 있던 화면 간 이동과 반복 작업을 보완했습니다. 라이브러리에서 선택한 승인 템플릿을 Studio에 바로 적용하고, 프레젠테이션과 슬라이드의 수명 주기를 화면에서 관리할 수 있도록 했습니다. 검수자는 이전 내용 버전과 변경점을 비교한 뒤 승인 조건을 확인할 수 있고, 실험 담당자는 두 실행의 지표와 데이터 해시, 카탈로그 해시를 비교하여 실패 사례를 라이브러리 탐색으로 이어갈 수 있습니다.

모바일에서는 입력과 미리보기를 전환하여 한 화면의 정보량을 줄였습니다. AI 생성 중에는 대기 안내를, 생성 후에는 실행 정보와 남은 일일 요청 수를 표시했습니다. 저장 충돌이 발생한 경우에는 현재 작업을 JSON으로 내려받은 뒤 최신 버전을 불러오도록 하여 사용자가 작성한 내용을 먼저 보관할 수 있게 했습니다.

이 흐름은 단위 및 통합 테스트 107개와 데스크톱 및 모바일 접근성 검사를 포함한 Playwright 시나리오 52개로 검증합니다. 콘텐츠, 온톨로지, 편집, 검수와 실험 담당자의 완료 기준을 역할 기반 시나리오 5개로 고정해 모두 통과했습니다. 외부 참여자 사용성 평가는 [과제와 기록 양식](user-study-protocol.md)까지 준비했으며, 수정 횟수와 막힌 단계의 기록 및 검증·집계 도구도 제공합니다. 실제 관찰은 다음 검증 단계입니다.

## 이번 구현에서 제외한 범위

- PDF와 마스터, 미디어, 표, 차트까지 복원하는 범용 디자인 추출 파이프라인
- 픽셀 단위 자유 배치 에디터, 협업 커서, 실시간 공동 편집
- 조직용 SSO, 이메일 계정 복구와 기업 수준의 권한 정책
- 대규모 벡터 인덱스 운영과 상용 모델 학습
- 외부 조직의 내부 데이터, 실제 사용자 연구, 상업 서비스 성과 수치

이번에는 데이터 등록부터 검수, 생성, 평가까지 하나의 흐름을 완성하고 검증하는 데 집중했습니다. 검색은 작은 데이터에서 기준선을 먼저 확인했습니다. 디자인 추출은 PPTX 앞쪽 최대 12장의 텍스트 상자, 좌표와 글자 크기를 온톨로지 초안으로 바꾸는 PoC까지 구현했으며, 이미지, 표, 차트와 마스터 복원은 후속 과제로 남겨두었습니다. 자체 계정의 작성자와 검수자 권한은 서버에서 분리합니다.

## 측정 계획

이번에 **확인한 항목**은 직접 작성한 개발용 질의 24개의 Hit@1과 MRR, DB 검색 후보와 페이지 경계, 동시 수정 충돌 처리, 세션 간 데이터 격리, 자동 품질 규칙, PPTX 12개 합성 왕복과 브라우저의 주요 기능 동작입니다. 공개 서비스에서 실제 OpenAI 생성부터 저장, 편집과 내보내기까지 확인하고, 개별 호출의 토큰 수와 생성 모듈 소요 시간도 기록했습니다. 검색 연산 시간에는 네트워크, DB 조회와 LLM 호출 시간이 포함되지 않습니다.

아직 **측정하지 않은 항목**은 운영자의 작업 시간 감소, 검수자 간 판단 일치율, 실제 사용자 선호, 다양한 입력에 대한 OpenAI 생성 품질, 응답 시간 분포와 장기 운영 비용입니다. 현재 역할 기반 시나리오는 기능 완료 여부를 재현하는 자동화이며, AI 검증은 같은 합성 예시를 사용한 연결과 기능 확인이므로 사람 대상 사용성 연구나 품질 벤치마크로 볼 수는 없습니다. 독립 평가자나 참여자가 필요하거나 비용 승인을 받아야 하는 결과는 아직 기록하지 않았습니다.

## 운영 기능 확장

작성자의 검수 요청과 검수자의 승인 권한, 계정과 버전별 감사 이력, 서버 중복 등록 방지, 템플릿 변경 전후의 시각적 비교와 수동 보완, PPTX 텍스트 위치 교정을 추가했습니다. 품질 평가 사본과 두 평가자의 판정, 실제 임베딩 검색 비교, 생성과 일괄 작업의 취소 및 복구도 지원합니다. [운영 기능 확장](operational-upgrades-2026-09-05.md)은 구현 내용과 아직 측정하지 않은 성과를 구분합니다.
