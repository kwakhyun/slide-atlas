# Product brief — Slide Atlas

## 문제와 가설

AI 프레젠테이션 PoC에서 생성 버튼 자체보다 어려운 문제는 **어떤 디자인을 재사용해도 되는지 설명하고, 잘못된 결과를 수정하며, 다음 실험의 근거를 남기는 것**이라고 가정했다. 미리디의 공개 채용 공고를 바탕으로 설정한 제품 가설이며, 실제 미리디 내부 병목을 조사했다는 주장은 아니다.

이번 범위의 사용자는 디자인 데이터 운영자와 PoC를 검증하는 프로덕트 엔지니어다. 이미지 파일만 모아두는 대신 전달 의도·레이아웃·슬롯·용량을 등록하고, 검수한 구조에서 내용을 바꾸고, 검색 품질을 같은 조건으로 비교할 수 있어야 한다.

## 핵심 여정과 완료 기준

| 여정        | 완료 기준                                                           | 구현 위치                      |
| ----------- | ------------------------------------------------------------------- | ------------------------------ |
| 데이터 등록 | UI 또는 JSON으로 등록, 잘못된 좌표·필수 슬롯·예시 데이터 거절       | Library / Zod schema           |
| 데이터 검수 | 초안 → 검수 대기 → 승인·수정 요청, 근거 필수, 수정 시 재검수        | Review / SQL transaction       |
| 구조 검색   | 전달 의도와 슬롯 요구를 점수에 반영, 근거 설명, 결과 없는 상태 제공 | Library / rankTemplates        |
| 내용 시각화 | 승인된 템플릿으로 브리프를 배치하고 원문을 보관                     | Studio / deterministic planner |
| 편집        | 스타일 대치 시 텍스트 유지, 슬롯 편집, 저장·되돌리기·복제           | Studio                         |
| 전달        | SVG / 구조 JSON / 편집 가능한 PPTX, 발표 모드                       | Export / Present               |
| 실험        | 동일 카탈로그·질의에서 두 검색기 비교, 개별 실패·실행 이력 저장     | Experiments                    |

## 왜 이 순서인가

1. **온톨로지 계약부터:** 모델보다 먼저 어떤 슬롯이 허용되는지 정의해야 입력·출력·검수에서 같은 기준을 쓸 수 있다.
2. **무료로 재현 가능한 경로:** API 키가 없는 평가자도 전체 운영 여정을 재현할 수 있도록 규칙 기반 경로를 기본으로 제공한다.
3. **AI는 경계가 있는 어댑터로:** 모델은 선택된 구조의 슬롯 텍스트만 반환한다. 도형·테마·승인 정책·DB를 직접 변경하지 않는다.
4. **실험을 제품 안으로:** 콘솔의 일회성 점수 대신 실행 기록, 카탈로그 버전, 개별 질의 결과를 화면과 JSON으로 남긴다.

## 의도적으로 제외한 것

- 임의의 PPTX/PDF를 자동 역설계하는 대규모 디자인 추출 파이프라인
- 픽셀 단위 자유 배치 에디터, 협업 커서, 실시간 공동 편집
- 기업 SSO·RBAC·운영자와 검수자의 직무 분리
- 벡터 검색·임베딩 인덱스·상용 모델 학습: 작은 데이터에서 기준선을 먼저 검증한다.
- 회사 내부 데이터, 실제 사용자 연구, 상업 서비스 성과 수치

이 범위는 구현 누락을 감추기 위한 것이 아니라 검증 가능한 하나의 운영 루프에 집중하기 위한 결정이다. 원본 문서 자동 추출과 역할 분리는 다음 단계의 별도 작업이다.

## 측정 계획

이번에 **측정한 것**은 24개 합성 개발 질의의 Hit@1·MRR, 동시 수정 충돌 처리, 세션 격리, 자동 품질 규칙과 브라우저 기능 동작이다. 검색 연산 시간은 네트워크·DB 읽기·LLM을 포함하지 않는다.

아직 **측정하지 않은 것**은 운영자 작업 시간 감소, 승인자 간 일치율, 실제 사용자의 선호, 실제 OpenAI 생성 품질·비용·응답 시간이다. 향후 운영자 3–5명에게 같은 등록/검수 과제를 주고 완료 시간, 되돌아간 단계, 주관적 어려움을 기록한 뒤 우선순위를 다시 정한다. 목표값을 실제 성과처럼 제시하지 않는다.
