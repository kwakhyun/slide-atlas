# 프로젝트 기획 — Slide Atlas

## 문제와 가설

AI 프레젠테이션 PoC를 운영 가능한 제품으로 발전시키려면 **재사용할 디자인을 선택하는 기준, 결과를 수정하는 과정, 다음 실험에 활용할 기록**이 필요하다는 가설에서 출발했습니다. 미리디의 공개 채용 공고를 참고해 설정한 가설이며, 회사 내부 업무를 직접 조사한 결과는 아닙니다.

주요 사용자는 디자인 데이터를 관리하는 운영자와 PoC를 검증하는 프로덕트 엔지니어로 설정했습니다. 전달 의도·레이아웃·슬롯·내용량을 데이터로 관리하고, 검수된 구조 안에서 내용을 편집하며, 동일한 조건으로 검색 품질을 비교할 수 있도록 설계했습니다.

## 주요 사용 흐름과 완료 기준

| 여정        | 완료 기준                                                           | 구현 위치                      |
| ----------- | ------------------------------------------------------------------- | ------------------------------ |
| 데이터 등록 | UI·JSON 등록, 좌표 오류·필수 슬롯 누락·잘못된 예시 데이터 차단      | Library / Zod schema           |
| 데이터 검수 | 초안 → 검수 대기 → 승인·수정 요청, 근거 필수, 수정 시 재검수        | Review / SQL transaction       |
| 구조 검색   | 전달 의도와 슬롯 요구를 점수에 반영, 근거 설명, 결과 없는 상태 제공 | Library / rankTemplates        |
| 내용 시각화 | 승인된 템플릿으로 브리프를 배치하고 원문을 보관                     | Studio / deterministic planner |
| 편집        | 스타일을 바꿔도 텍스트 유지, 슬롯 편집, 저장·되돌리기·복제          | Studio                         |
| 전달        | SVG / 구조 JSON / 편집 가능한 PPTX, 발표 모드                       | Export / Present               |
| 실험        | 동일 카탈로그·질의에서 두 검색기 비교, 개별 실패·실행 이력 저장     | Experiments                    |

## 구현 순서를 정한 이유

1. **데이터 규칙을 먼저 정의했습니다.** 허용되는 슬롯과 제약 조건을 정해 등록·생성·검수 단계에서 같은 기준을 사용하도록 했습니다.
2. **API 키 없이 체험할 수 있게 했습니다.** 평가자가 전체 사용 흐름을 확인할 수 있도록 규칙 기반 생성을 기본으로 제공합니다.
3. **AI가 변경할 수 있는 범위를 제한했습니다.** 모델은 선택된 템플릿의 슬롯 텍스트만 반환하며, 도형·테마·승인 정책·DB를 직접 변경하지 않습니다.
4. **실험 결과를 서비스에 남겼습니다.** 실행 이력, 카탈로그 버전, 개별 질의 결과를 화면에서 확인하고 JSON으로 내려받을 수 있도록 했습니다.

## 이번 구현에서 제외한 범위

- 임의의 PPTX/PDF를 자동 역설계하는 대규모 디자인 추출 파이프라인
- 픽셀 단위 자유 배치 에디터, 협업 커서, 실시간 공동 편집
- 기업 SSO·RBAC·운영자와 검수자의 직무 분리
- 벡터 검색·임베딩 인덱스·상용 모델 학습
- 회사 내부 데이터, 실제 사용자 연구, 상업 서비스 성과 수치

이번에는 데이터 등록부터 검수, 생성, 평가까지 하나의 흐름을 완성하고 검증하는 데 집중했습니다. 검색은 작은 데이터에서 기준선을 먼저 확인했으며, 원본 문서에서 디자인을 추출하는 기능과 사용자 역할에 따른 권한 분리는 후속 과제로 남겨두었습니다.

## 측정 계획

이번에 **확인한 항목**은 직접 작성한 개발용 질의 24개의 Hit@1·MRR, 동시 수정 충돌 처리, 세션 간 데이터 격리, 자동 품질 규칙, 브라우저에서의 주요 기능 동작입니다. 공개 서비스에서 실제 OpenAI 생성부터 저장·편집·내보내기까지 확인하고, 개별 호출의 토큰 수와 생성 모듈 소요 시간도 기록했습니다. 검색 연산 시간에는 네트워크·DB 조회·LLM 호출 시간이 포함되지 않습니다.

아직 **측정하지 않은 항목**은 운영자의 작업 시간 감소, 검수자 간 판단 일치율, 실제 사용자 선호, 다양한 입력에 대한 OpenAI 생성 품질, 응답 시간 분포와 장기 운영 비용입니다. 현재 AI 검증은 같은 합성 예시를 사용한 연결·기능 확인이므로 품질 벤치마크로 볼 수는 없습니다. 다음 단계에서는 운영자 3~5명에게 같은 등록·검수 과제를 수행하도록 하고, 완료 시간과 되돌아간 단계, 어려웠던 부분을 기록할 계획입니다. 이 결과를 바탕으로 우선순위를 조정하되, 계획한 목표를 실제 성과로 표시하지는 않습니다.
